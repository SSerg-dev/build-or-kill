# Plan 01-01: Native One-Page UI Shell

<objective>
Create the native HTML/CSS/JavaScript application shell for the Build or Kill MVP. This plan delivers the one-page flow, required input validation, inline UI state areas, stale-result marking, and localStorage restoration foundation.
</objective>

<context>
Must follow `.planning/phases/01-mvp-validation-app/01-CONTEXT.md` decisions:
- D-01: one-page flow
- D-02: form stays above result
- D-03: stale old result marker
- D-04: localStorage only for old/last result, not a dashboard/history
- D-05: short explanation plus immediately available form
- D-14: native HTML/CSS/JS, no Angular
- D-15: lightweight framework-free UI unless a later phase adds real frontend complexity
</context>

<must_haves>
- D-01: The form, clarification area, loading state, and result area live on one continuous page.
- D-02: The form remains visible above the result after analysis.
- D-03: Editing input after a result exists marks that result stale.
- D-04: localStorage stores only the old/last result snapshot and must not become a history/dashboard.
- D-05: First load shows a short validation-focused explanation above an immediately available form.
- D-14: Phase 1 uses native HTML, CSS, and JavaScript.
- D-15: Do not introduce Angular or another frontend framework in this phase.
</must_haves>

<tasks>

## Task 1: Create minimal native app scaffold

**Type:** create
**Files:** `package.json`, `src/index.html`, `src/styles.css`, `src/app.js`

**Action:**
- Add npm scripts for running the MVP locally.
- Create a single `index.html` page with:
  - short product explanation
  - idea form
  - inline validation area
  - clarification area placeholder
  - loading state placeholder
  - result area placeholder
- Link `styles.css` and `app.js`.

**Verify:**
- Opening or serving the page displays the form immediately.
- No Angular or frontend framework dependency exists.

**Acceptance Criteria:**
- User can see product explanation and form on first load.
- App surface is a real tool screen, not a marketing landing page.

## Task 2: Implement required form fields and validation

**Type:** implement
**Files:** `src/index.html`, `src/app.js`

**Action:**
- Add fields:
  - idea name, optional
  - product description, required
  - target audience, required
  - main pain/problem, required
  - optional notes
- Add submit handler.
- Block submit and show inline validation when required fields are empty.

**Verify:**
- Empty required fields block analysis.
- Optional fields do not block analysis.

**Acceptance Criteria:**
- Covers INTAKE-01 through INTAKE-05.

## Task 3: Add one-page UI state management

**Type:** implement
**Files:** `src/app.js`, `src/styles.css`

**Action:**
- Manage UI states:
  - idle
  - validation error
  - clarification needed
  - analyzing/loading
  - result ready
  - error
- Keep the form above all generated UI.
- Add stale-result marker when the user edits input after a result exists.

**Verify:**
- Editing any input after result display marks the current result stale.
- Result is not removed automatically.

**Acceptance Criteria:**
- D-01, D-02, and D-03 are visible in app behavior.

## Task 4: Add localStorage last-result persistence

**Type:** implement
**Files:** `src/app.js`

**Action:**
- Persist only the last result and the input snapshot used to produce it.
- Restore last result on page load as stale/restored local result when available.
- Do not implement multi-result history, accounts, dashboard, or analytics.

**Verify:**
- Refreshing the page can restore the last local result.
- Only one result snapshot is stored.

**Acceptance Criteria:**
- D-04 is implemented without scope creep.

</tasks>
