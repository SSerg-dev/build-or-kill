# Plan 01-02: AI Adapter, Schema, Clarification, and Mock Fallback

<objective>
Implement the server-side AI contract for Build or Kill using OpenAI Responses API with Structured Outputs JSON schema, plus deterministic mock/demo fallback. This plan connects the UI shell to a safe `/api/analyze` endpoint and enforces clarification-vs-final-result behavior.
</objective>

<context>
Must follow `.planning/phases/01-mvp-validation-app/01-AI-SPEC.md`:
- OpenAI Responses API with Structured Outputs JSON schema
- two output modes: `clarification_needed` and `final_result`
- no web search, market scraping, competitor scraping, or fabricated research
- API key must stay server-side

Must follow `.planning/phases/01-mvp-validation-app/01-CONTEXT.md`:
- D-06: inline clarification under form
- D-07: short field per clarification question
- D-08: auto-run final analysis after all clarification answers are filled
- D-09: block final analysis when clarification answer is empty
</context>

<must_haves>
- D-06: Weak or incomplete input renders 2-3 clarification questions inline below the form.
- D-07: Each clarification question has its own short text field.
- D-08: Once all clarification answers are filled, the app automatically runs final analysis with those answers as context.
- D-09: Empty clarification answers block final analysis and show inline validation.
</must_haves>

<tasks>

## Task 1: Add minimal server endpoint

**Type:** create
**Files:** `server/index.js`, `package.json`

**Action:**
- Add a minimal Node server that serves static files from `src/`.
- Add `POST /api/analyze`.
- Read `OPENAI_API_KEY`, `OPENAI_MODEL`, and demo/mock mode from environment.
- Ensure browser code never receives the API key.

**Verify:**
- Local server starts.
- Static app loads.
- `/api/analyze` accepts JSON input and returns JSON output.

**Acceptance Criteria:**
- Live AI integration has a safe server boundary.

## Task 2: Define structured output schemas

**Type:** implement
**Files:** `server/ai/schemas.js`

**Action:**
- Define JSON schema for a discriminated result:
  - `clarification_needed`
  - `final_result`
- Enforce:
  - exactly one verdict for final result
  - confidence score 0-100
  - five required roles
  - required strengths, risks, MVP scope, validation experiments, and next actions
  - advisory disclaimer

**Verify:**
- Mock and live outputs can be validated against the same schema.

**Acceptance Criteria:**
- Covers AI-01 through AI-09 and REL-02.

## Task 3: Write advisory prompt

**Type:** implement
**Files:** `server/ai/prompts.js`

**Action:**
- Create a system prompt that:
  - defines the five roles
  - requires structured reasoning but concise output
  - forbids invented market data and competitor research
  - requires clarification for weak inputs
  - states that verdicts are advisory, not deterministic
  - requires output based only on provided input

**Verify:**
- Prompt references all required roles and restrictions from SPEC and AI-SPEC.

**Acceptance Criteria:**
- Covers QUAL-01 through QUAL-05.

## Task 4: Implement OpenAI adapter and mock fallback

**Type:** implement
**Files:** `server/ai/advisorClient.js`, `server/ai/mockAdvisor.js`, `server/index.js`

**Action:**
- Implement OpenAI Responses API call with `text.format` JSON schema.
- Add mock mode/fallback output for demos and offline reliability.
- Add basic error handling:
  - invalid request
  - OpenAI failure
  - malformed response
  - forbidden output claim
- Retry at most once on schema failure, then fall back to safe error/mock behavior.

**Verify:**
- Mock mode produces clarification for weak inputs.
- Mock mode produces final result for strong inputs.
- Server returns safe errors without leaking internals.

**Acceptance Criteria:**
- Covers REL-01, REL-02, and REL-03.

## Task 5: Connect frontend to analyze endpoint and clarification flow

**Type:** implement
**Files:** `src/app.js`

**Action:**
- Submit validated input to `/api/analyze`.
- If response is `clarification_needed`, render 2-3 inline questions under the form.
- Render short text fields for each question.
- Block empty clarification answers.
- After all answers are filled, automatically submit final analysis with original input plus clarification answers.
- Show loading state during requests.

**Verify:**
- Weak input triggers inline clarification and no final verdict.
- Filled clarification answers automatically run final analysis.
- Empty clarification answer blocks final analysis with inline validation.

**Acceptance Criteria:**
- Covers CLAR-01 through CLAR-03.
